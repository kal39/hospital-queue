# Workflow: PR

Open a GitHub pull request for work on the current branch, linked to an issue, with a description that matches `.github/PULL_REQUEST_TEMPLATE.md`.

**Input:** GitHub issue number (e.g. `123`) or URL; optional base branch (default: `main`).

---

## How teammates run this

**Any chat UI:**

```text
Follow docs/workflows/pr.md.

Issue: #123
Base: main
Action: plan only | create PR
```

**Cursor:** Invoke the `pr` skill.

**CLI (after plan is approved):** run the `gh pr create` command the agent outputs, or ask the agent to run it with network permission.

---

## Prerequisites

- [ ] `gh` authenticated (`gh auth status`) and default repo is `LevCodeX/hospital-queue` (`gh repo view`)
- [ ] Current branch is pushed (`git push -u origin HEAD` if needed)
- [ ] Branch is not the base branch (e.g. not `main`)
- [ ] Issue exists and is **open** (work is done on the branch; the issue closes on merge)
- [ ] User chose **plan only** or **create PR**

---

## Step 1 — Load issue

```bash
gh issue view <N> --json title,body,number,state,labels
```

Extract:

| Source | Use for |
| ------ | ------- |
| Title | PR title stem (strip leading emoji/type if duplicated) |
| Body | Summary bullets, AC / test plan, traceability (`US-*`, `REQ-*`, PROJECT.md links) |
| Labels | Change type hint if present |

If the issue is closed, stop and confirm with the user before continuing.

---

## Step 2 — Inspect the diff

From the repo root on the current branch:

```bash
git fetch origin <base>
git diff --stat origin/<base>...HEAD
git diff origin/<base>...HEAD
```

Use the diff (and `PROJECT.md` when behavior is unclear) to understand what changed. Do not invent changes not in the diff.

---

## Step 3 — Choose change type

Use the emoji-first type that best matches the work:

| Type        | Emoji |
| ----------- | ----- |
| Bug         | 🦠    |
| Enhancement | ✨    |
| Refactor    | ♻️    |
| Feature     | 🚀    |
| Docs        | 📝    |
| Test        | 🧪    |
| Config      | 🔧    |
| Perf        | ⚡    |
| Security    | 🔒    |
| Cleanup     | 🧹    |

---

## Step 4 — Plan (always, before create)

Show the user a preview:

| Field | Value |
| ----- | ----- |
| Title | `<emoji> <Area>: <imperative outcome>` (no `**`, no `[]` in title) |
| Base | `main` (or user override) |
| Head | current branch |
| Closes | `#<N>` |

**Title rules:** same emoji as the type line in the body; plain text after the emoji prefix; match team style in `.github/PULL_REQUEST_TEMPLATE.md`.

**Body structure** (fill all sections; content below `---` is generated by you):

```markdown
**<emoji> <Type>**: <one or two sentences, ultra terse, present tense>

<details>
<summary>Description</summary>

- <bullet per logical change>
- <pull test plan from issue AC when present>

</details>

---

<details><summary>Diagram</summary>

<diagram or short table per diagram policy below>

</details>

<details><summary>File walkthrough</summary>

- `path/to/file` — terse what changed
- ...

</details>
```

### Diagram policy

Diagram only spatial/topological information. Text everything else.

Diagram when ALL of: spatial structure, absent from codebase, ≤7 elements per view.
Text when ANY of: sequential, comparative, hierarchical, tabular, already in code.

Prefer Mermaid in a fenced block (` ```mermaid `). Prefer top-down (`flowchart TD`). Split or use a table if >7 nodes.

### Description rules

- Present tense: "Adds queue call-next endpoint" not "This PR adds…"
- No hedging ("likely", "probably"); no praise or marketing language
- Do not duplicate the opening type line inside Description bullets
- Do not include review feedback or speculative scope
- Skip diagram if the change is trivial (typos, single-file config tweak) — say so in plan instead

If **plan only**, stop here.

---

## Step 5 — Create on GitHub

Run only after the user approves the plan and asked to **create PR**.

```bash
gh pr create \
  --repo LevCodeX/hospital-queue \
  --base <base> \
  --head "$(git branch --show-current)" \
  --title "<emoji> Area: outcome" \
  --body "$(cat <<'EOF'
<paste full body>
EOF
)"
```

Add `Closes #<N>` (or `Fixes #<N>`) in the body if not already present so merge closes the issue.

After creation, reply with the PR URL and a one-line summary.

---

## Do not

- Open a PR from the base branch without explicit user intent
- Force-push or amend unless the user asks (see team git rules)
- Use `docs/prd/` as implementation truth (use `PROJECT.md` and issue links)
- Commit secrets or paste tokens into the PR body

---

- [ ] `Closes #<N>` present
- [ ] User has PR URL
